# 部署与备份

## 部署形态

| 项 | 约定 |
|----|----|
| 目录 | `~/apps/issue-desk`（源码 + `.env`，`.env` 权限 600，不入库） |
| 访问 | `APP_BIND:APP_PORT`，内网部署时绑定内网地址 |
| 容器 | `issue-desk-app-1`、`issue-desk-db-1`，`restart: unless-stopped` |
| Volume | `issue-desk_db-data`（数据库）、`issue-desk_storage`（附件） |

具体主机、端口与账号记录在项目笔记，不写进仓库。管理员创建成功后，从 `.env` 移除 `SEED_ADMIN_PASSWORD`。

## 更新

```bash
# 在开发机仓库根目录
git archive --format=tar HEAD | ssh <user>@<host> 'cd ~/apps/issue-desk && tar -xf -'
ssh <user>@<host> 'cd ~/apps/issue-desk && sudo docker compose up -d --build'
```

迁移在容器启动时自动执行（`prisma migrate deploy`）。

## HTTPS 反代示例（内网证书自备，证书与密码不入库）

```nginx
server {
  listen 443 ssl;
  server_name issue-desk.internal;
  ssl_certificate     /etc/ssl/issue-desk/fullchain.pem;
  ssl_certificate_key /etc/ssl/issue-desk/privkey.pem;
  client_max_body_size 25m;
  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}
```

改用 HTTPS 时，把 `.env` 的 `APP_BASE_URL` 改为 `https://…`，会话 cookie 会自动加 `Secure`。同时把 `APP_BIND` 改为 `127.0.0.1`，只让反代访问。

## 备份

脚本 `docker/backup.sh`：用 `pg_dump -Fc` 导出数据库，用 tar 打包附件 volume（只读挂载）。先写临时文件，校验通过（`pg_restore --list`、`gzip -t`）后再改名。备份保存在本机，文件权限 600，默认保留 14 天。

```bash
# 手动执行（变量均有默认值）
APP_DIR=~/apps/issue-desk BACKUP_DIR=~/backups/issue-desk KEEP_DAYS=14 sh ~/apps/issue-desk/docker/backup.sh
```

定时执行（部署用户的 crontab，每天 03:15）：

```cron
15 3 * * * /bin/sh $HOME/apps/issue-desk/docker/backup.sh >> $HOME/backups/issue-desk/backup.log 2>&1
```

部署用户需要在 docker 组内（cron 中不用 sudo）。数据库与附件要一起备份、一起恢复，二者通过 `storageKey` 对应。

## 恢复

```bash
cd ~/apps/issue-desk
sudo docker compose stop app
sudo docker compose exec -T db pg_restore -U issue_desk -d issue_desk --clean --if-exists < ~/backups/issue-desk/db-<TS>.dump
sudo docker run --rm -v issue-desk_storage:/data -v ~/backups/issue-desk:/in alpine \
  sh -c 'cd /data && tar -xzf /in/storage-<TS>.tgz'
sudo docker compose start app
```

注意：`audit_logs`、`activities` 两张表有只增触发器，`pg_restore --clean` 会先删表再重建，所以恢复不受影响。不要对这两张表执行 UPDATE 或 DELETE。

## 停用提醒任务

在 `.env` 设置 `REMINDERS_ENABLED=false`，然后执行 `docker compose up -d`。课题的创建、编辑和状态变更不受影响。
