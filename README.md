# 课题管理系统（issue-desk）

内部团队用的 Web 应用：多客户、多会谈/跟进批次、多课题。记录过程，追踪是否办完，分析负荷与逾期，到期提醒，留下可归档的证据。规格见 `projects/课题管理系统/spec/课题管理系统设计/`（v0.1.1）。

## 技术栈

| 层 | 选型 |
|----|------|
| 应用 | Next.js 15（App Router）+ TypeScript 严格模式 |
| 数据 | PostgreSQL 16 + Prisma 6（`prisma/migrations`） |
| 认证 | 邮箱 + 密码（bcrypt），会话入库，cookie 只存随机令牌 |
| 富文本 | Tiptap（加粗、列表、图片），服务端 sanitize-html 消毒 |
| Excel | exceljs（导入、导出），jszip（证据打包） |
| 部署 | Docker Compose：`app` + `db`，两个 volume（数据库、附件） |

与规格默认假设的差异：认证没有用 Auth.js，改为自建数据库会话（能力相同：邮箱密码、会话入库、可退出、连续失败锁定）。原因是 Auth.js v5 仍为 beta，Credentials 模式下官方不建议数据库会话。

## 空库启动

```bash
cp .env.example .env
# 填写 POSTGRES_PASSWORD、AUTH_SECRET（openssl rand -base64 48）、
# SEED_ADMIN_EMAIL、SEED_ADMIN_PASSWORD（至少 10 位）
docker compose up -d --build
```

启动时依次执行：数据库迁移 → 种子（优先级 高/中/低、课题类型、来源、默认设置、管理员）→ 启动应用。种子不创建任何客户、会谈或课题。管理员创建成功后，从 `.env` 删除 `SEED_ADMIN_PASSWORD`，再执行 `docker compose up -d` 重建容器。

本地开发：

```bash
npm ci
# .env 中填写 DATABASE_URL 指向本地 PostgreSQL
npx prisma migrate deploy && node prisma/seed.mjs
npm run dev
```

## 手工新建一条课题

1. 登录后点顶栏「新建课题」。
2. 「客户」选已有客户，或点「同时新建客户」直接输入名称。番号自动取该客户的下一号。
3. 填写標題、優先度、記載日（默认今天）、期限、担当（默认自己）。在完了条件、問題点、解決案中可以直接粘贴截图。
4. 点「创建并打开」。点「创建后再建一条」会保留客户与会谈。

之后在详情页「追加问题 / 追加解决」，历史不会被覆盖。

## 导入 Excel（可选）

导航「导入」→ 上传 `.xlsx` → 预览 → 确认 → 结果。

- 识别表头区（客先、会谈、更新日、更新者、会谈信息、填写口径），以及「詳細」拆分成的問題点/解決案。
- 期限、記載日支持日期、`yyyy-mm-dd` 文本和 Excel 序列数字（例如 46324 → 2026-10-29）。
- 空行和只有番号的占位行会跳过。缺标题的行会导入，并标「标题待补」。
- 記載日跨多天时，默认按日期另建「跟进」批次。预览里可以改为全部归入表头会谈。
- 番号已存在时默认「仅填空」，問題点/解決案只追加。
- 源表中的「已完成/完了」导入为「待客户确认」，补齐证据与客户确认后才能完成。「已回答」保持已回答。

系统不会自动导入任何文件。

## 四项能力怎么验收

| 能力 | 在哪里看 |
|------|----------|
| 追踪 | 课题详情：状态流转、时间线（字段变更旧值→新值）、多轮问题点/解決案、关联课题、待谁处理 |
| 分析 | 概览：未完结、已逾期、七日到期、长期待确认、高优先缺项，按客户/担当/状态/优先级/待谁处理计数，响应天数；每块可点进对应筛选 |
| 提醒 | 顶栏铃铛与「提醒」页：临期、逾期、长期待客户确认、高优先缺担当/缺期限，每课题每规则每天最多一条 |
| 归档依据 | 证据库、完成门禁（至少一份证据 + 客户确认人与日期）、操作日志（只增，数据库触发器拒绝修改与删除）、xlsx/zip 导出 |

图文限制：正文图片只收 jpg/png/gif/webp，单张默认上限 10MB。证据还可以收 pdf/doc/docx/xls/xlsx/txt，单个默认上限 20MB。服务端按扩展名、MIME 和文件头三重校验。音视频一律拒绝，提示「本系统不支持视频或语音文件」。系统中没有播放器。

## 测试

```bash
npm test            # 单元测试（状态机、门禁、附件规则、日期、提醒规则、消毒、导入解析）
npx tsc --noEmit
```

端到端验收脚本 `e2e/acceptance.py`（Playwright）只能对独立测试实例运行，用法见脚本头部注释。
